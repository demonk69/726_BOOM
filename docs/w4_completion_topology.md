Branch resolution is generated by the INT ALU: `io_brinfo_valid = is_br | is_jalr` at `top.v:221555`, propagated by `ALUExeUnit_1` at `top.v:225513-225528`, and reaches ROB branch update signals at `top.v:279583-279586`. Branch result completion also uses INT response/ROB port 1.

The eventual load response returns through the LSU-to-`mem_units_0_io_ll_iresp` path and then PRF/ROB port 0.

## Baseline Consequences

- Two physical integer PRF writes exist, but they are asymmetric: port 0 is the long-latency arbiter path and port 1 is the INT ALU/MUL/DIV/branch/CSR path.
- Three regular integer wakeups do not mean three independent writebacks. One is speculative fast wakeup from issue; one is the corresponding slow non-bypassable INT result; one is the long-latency arbiter completion.
- The three execution bypass buses are pipeline taps from the INT ALU path, not three PRF write ports.
- Four ROB writeback inputs include two FP-domain ports. The integer-only topology uses general ports 0 and 1, plus the LSU clear-busy sidebands where applicable.
- W3 HLS remains fixed MEM/INT dual issue with serialized completion. The generated BOOM topology is a reference target, not evidence that W4A exists in HLS.

## Blockers Before W4A

- A required W4A contract must decide whether to reproduce the generated BOOM asymmetry or define a different arbitration policy for simultaneous load and INT completion.
- Fast wakeup must be paired with poison/replay handling; it cannot be equated to committed PRF writeback.
- Branch recovery ordering must remain ahead of younger completion side effects.
- MEM AGU request acceptance, LSU clear-busy, load response writeback, and ROB completion are distinct events and must not be collapsed into one generic completion.
- The integer-only W4A scope must explicitly exclude or model the generated FP-to-int arbiter input and ROB ports 2-3.

## Final HLS Mapping

The W4 product uses exactly three named persistent completion fields: `CompletionPendingState::load_response`, `mem_execute`, and `int_execute`. These named slots replace the need for a dynamically indexed completion-buffer array and are HLS-safe ordinary struct members. Capacity is exactly three because there are exactly three such `RobCompleteEvent` members, every source-to-port builder maps one of them, all service loops are bounded by `COMPLETION_PENDING_SLOTS`, and a static assertion fixes that constant to 3. This statement does not claim array or partition syntax for the completion buffer.

Final random evidence reaches `peak_completion_sources=3` and performs 19,419 exact ROB-complete checks. The fourth general ROB response class remains unsupported in the integer HLS subset, and FP lane 2 is cleared rather than accepted as a canonical source.
