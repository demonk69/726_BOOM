# PF4 Artifact Manifest

This manifest uses the repository policy classes from
`docs/gate_artifact_policy.md`.

## CURATED_EVIDENCE

The following repository-resident evidence is durable and required at the PF4
commit:

- PF4 verdict and contracts: `pf4_results.md`,
  `pf4_branch_recovery_architecture.md`,
  `pf4_prediction_resolution_truth_table.csv`,
  `pf4_ftq_prediction_lookup_contract.md`, and `pf4_redirect_priority.md`.
- Source and directive provenance: `baseline_manifest.md`,
  `source_hashes_before.txt`, `source_hashes_after.txt`, and
  `directive_audit.md`.
- Canonical synthesis evidence: `pf4_canonical_synthesis.csv`,
  `hls_synthesis_timing_audit.md`,
  `reports/gate5_4_pf4_canonical/module_csynth_summary.csv`,
  `reports/gate5_4_pf4_canonical/module_csynth/boom_core_top.log`, and
  `reports/gate5_4_pf4_canonical/module_csynth/boom_core_top.time`.
- Full-core RTL evidence: `full_core_rtl/generation_provenance.md`,
  `full_core_rtl/source_freshness_manifest.csv`,
  `full_core_rtl/full_core_rtl_matrix.csv`, and every JSONL trace in
  `full_core_rtl/traces/`.
- Preservation evidence: `pf4_preservation_matrix.csv`,
  `reports/gate5_4_pf4_preservation_pf1/module_csynth_summary.csv`,
  `reports/gate5_4_pf4_preservation_pf2/module_csynth_summary.csv`, and
  `reports/gate5_4_pf4_preservation_pf3/module_csynth_summary.csv`.
- PF4AR evidence: `pf4_artifact_provenance_repair.md` and
  `durable_artifact_hashes.csv`.

Every path above is repository-relative. `durable_artifact_hashes.csv`
enumerates and hashes each selected file except itself; the Git tree anchors
the checksum inventory without a circular self-hash.

## REPRODUCIBLE_WORKSPACE

The original generated-RTL locations were:

- Canonical `boom_core_top` synthesis:
  `/tmp/boom_hls/pf4/canonical/boom_hls_gate5_4_pf4_canonical_boom_core_top/solution_module/syn/verilog`.
- Test-only Product-FTQ full-core RTL:
  `/tmp/boom_hls/pf4/full_core_rtl/boom_core_pf4_rtl_top_hls/solution_pf4_rtl/syn/verilog`.

These paths contain generated RTL and tool solution state, so policy classifies
them as `REPRODUCIBLE_WORKSPACE`, not `CURATED_EVIDENCE`.
`PATH_EXISTS_AT_COMMIT_REQUIRED=false`. Their absence after successful evidence
extraction is expected. Any `/tmp/boom_hls/pf4` path retained in a log, summary,
or preservation matrix is execution provenance with the same classification.

The canonical top was `boom_core_top`, generated by
`scripts/run_module_csynth.sh` with `scripts/module_csynth.tcl`. The test-only
full-core top was `boom_core_pf4_rtl_top`, generated and tested by
`scripts/gate5_4/run_pf4_full_core_rtl.sh`. Both are tied to the source hashes
retained by the durable evidence above.

Repository report/program-image writes made by legacy runners remain
diagnostic or historical unless explicitly selected above. `src/boom_all.cpp`
remained excluded from generation, compilation, RTL, synthesis, and verdicts,
with its baseline hash unchanged.
